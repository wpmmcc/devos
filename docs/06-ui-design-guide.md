## 文档 6：可学习的 UI 界面参考与核心页面设计规范（`06-ui-design-guide.md`）

### 6.1 5 个最值得直接对标的标杆 UI（学什么、怎么用）

1. **LocalWP（Local by Flywheel）—— 学“面向小白的本地环境控制感”**
* **可借鉴点：** 左侧简洁的项目列表（每个项目带绿/灰运行圆点）、顶部右侧醒目的单一主按钮（Start / Stop Site）+ 「Open Site」快捷入口、底部用最克制的 Tabs 切换基础信息与工具，完全隐藏了底层 Nginx/PHP/MySQL 容器的复杂配置。
* **落地借鉴：** 你的 DevOS 左侧栏和顶部环境状态条可直接对标 LocalWP 的清晰度。


2. **OrbStack —— 学“高信任感的容器状态与低噪日志体验”**
* **可借鉴点：** 极度干净的原生桌面质感、零视觉冗余、容器启停反馈极快；健康状态、端口映射和资源占用一目了然，不会堆满花哨的仪表盘图表。
* **落地借鉴：** 你的「环境体检向导」和「环境状态详情抽屉」学习 OrbStack 的克制排版与明确状态提示。


3. **Linear —— 学“极简看板、Issue 列表与详情抽屉”**
* **可借鉴点：** 看板卡片只保留 3 个核心元素（编号 + 标题 + 状态/优先级微标），点击卡片从右侧平滑滑出详情抽屉，不打断当前上下文；状态流转清晰流畅。
* **落地借鉴：** 你的 4 列看板（`待开发` / `开发中` / `待我测试` / `已完成`）和 `Issue 中心` 直接采用 Linear 的信息密度和右侧抽屉交互。


4. **Vercel Preview Comments / Marker.io —— 学“零门槛网页测试反馈”**
* **可借鉴点：** 在预览页面边缘悬浮一个极简工具条（只有“批注/提问题”和“查看已有反馈”），用户点击页面任意位置就能画框留言，后台自动附带浏览器环境与报错信息。
* **落地借鉴：** 你的 Web 测试预览窗口直接采用这种“所见即所提”的悬浮反馈条。


5. **Raycast 表单 / n8n 手动触发面板 —— 学“把后端脚本变成可视化按钮”**
* **可借鉴点：** 把命令行参数渲染成带中文标签、默认值、文件选择器的干净表单，底部一个「运行」主按钮，右侧/下方直接展示结构化的运行结果与可下载文件卡片。
* **落地借鉴：** 你的 `devos.run.json` 后端脚本测试台采用此布局，彻底消灭小白对终端命令行的恐惧。



### 6.2 DevOS 核心界面信息架构（4 个主视图）

整个应用采用 **「左侧窄项目栏（220px） + 顶部统一环境控制条（52px） + 主工作区」** 的经典三段式桌面布局：

* **顶部统一控制条（全局常驻）：**
* 左侧：当前项目名 + 三态模式标签（如 `本地开发中`）。
* 中间：环境健康状态灯（`Web 运行中` / `脚本环境就绪`）+ Agent 连接灯（`已连接：Factory Droid`）。
* 右侧：主操作按钮（`启动/停止环境`、`打快照/还原`、`在 Agent 中打开`）。


* **主工作区 4 个核心 Tab：**
1. **看板与进度（Board）：** 仅 4 列（`待开发`、`开发中`、`待我测试`、`已完成`）。`待我测试` 列卡片高亮显示「验收清单（0/4）」进度，点开直接跳转测试台。
2. **测试与预览台（Test & Preview）：**
* **Web 模式：** 左侧/主区域是内嵌实时预览页 + 顶部悬浮「提问题」按钮；右侧折叠面板展示当前卡片的「白话验收清单（可逐条勾选）」。
* **脚本模式：** 左侧选择 `devos.run.json` 定义的任务列表；中间是自动生成的参数表单与「运行测试」按钮；下方展示运行状态、输出文件预览与「一键转为 Issue」按钮。


3. **Issue 反馈中心（Issues）：** 按 `待修复 (open)`、`待我复测 (ready_for_retest)`、`已关闭 (closed)` 分组。`待我复测` 卡片顶部醒目展示 Agent 写的白话修复说明 + 「去复测」/「确认已修好」/「还是不行」三个按钮；技术日志与堆栈默认折叠在底部。
4. **项目资产（Assets）：** 左侧目录树切换「项目需求」、「项目标准（给 AI 的硬规范）」、「使用文档」、「避坑知识库」，右侧为干净的 Markdown 预览与编辑区。



### 6.3 面向非开发用户的视觉与交互底线

* **留白优先，拒绝监控大屏风：** 禁止把 CPU/内存折线图、滚动黑底终端日志直接铺在首页；首页核心视觉焦点永远只有两件事——**“现在能点开看/测吗？”** 和 **“有哪些待我测试或复测的卡片？”**。
* **确定性反馈：** 任何涉及 Docker/DDEV 的耗时操作（大于 1 秒）必须给分阶段进度提示（例如：`1/3 正在检查容器引擎 -> 2/3 正在启动数据库 -> 3/3 预览地址已就绪`），绝不让界面无声转圈。
